# Reproducción del sublote de precio

Usar el entorno virtual de r1-pmv. Conservar los JSON de cada corrida por su identificador. Para las salidas de texto elegir un nombre nuevo. La selección previa tiene SHA-256 `59c3bc38c1761cecd153296f89ddc6367b7d668d89d3c68809a3f5660d0a0581`. Las fechas de los ficheros 03-REVAL están expresadas en UTC. Las corridas que comienzan el 21/11 UTC corresponden al 20/11 en Lima.

1. Desde la raíz, contrastar `git -C r1-pmv rev-parse HEAD`, `git -C r1-pmv status --porcelain` y los digest por ruta de [fuentes.json](fuentes.json). El manifiesto comprende Python, HTML, JS, CSS y SVG de las aplicaciones, configuración y plantillas. El paquete de entrega tiene su propio manifiesto de 150 entradas. `preparar_paquete.py` del [corte 02](../02-INTEGRAL-20261120/REPRODUCIR.md) exige un destino nuevo y coteja los archivos con los hashes publicados. `vercel inspect https://minimarket-academico-auditoria02.vercel.app` identificó el despliegue Ready `dpl_6GBoMJLowvLxrqEJUnZrw5G8XNwL` en esta sesión.
2. En r1-pmv, establecer `APP_ENV=test` y ejecutar `.venv/Scripts/python.exe manage.py test catalog sales.test_audit03r_review sales.test_audit03s_review -v 2`. La suite crea su SQLite en memoria. Para Chrome local ejecutar desde la raíz `r1-pmv/.venv/Scripts/python.exe auditoria_por_etapas/resultados/soporte/audit03_reval_run.py`. El lanzador crea otra base aislada, roles y servidor de loopback. El puerto y los ficheros de cada ejecución son independientes.
3. Para las carreras, fijar `AUDIT03_PG_BIN` al directorio bin de PostgreSQL 17.10 (se usó el preparado para 02 bajo TEMP/etapa02-pg17-bin/bin). Ejecutar `r1-pmv/.venv/Scripts/python.exe auditoria_por_etapas/resultados/soporte/audit03_reval_pg.py`. Inicializa y detiene un clúster exclusivo. El JSON contiene por caso las dos conexiones y si el PID bloqueador era el ganador. No se ensayó ordenación por tiempos empatados en este sublote.
4. Para HTTPS usar el proyecto ficticio de 02, credenciales exclusivamente de ensayo y su base temporal vigente. Verificar primero proyecto, alias, despliegue y los 150 hashes. Seguir el [procedimiento privado de preparación de 02](../02-INTEGRAL-20261120/REPRODUCIR.md) para `MMSTAGE` y `MM_PLAYWRIGHT`; conservarlos fuera de la evidencia. Se requiere turno abierto del vendedor ficticio y sin borrador activo. Ejecutar `r1-pmv/.venv/Scripts/python.exe auditoria_por_etapas/resultados/evidencias/03-PRECIO-20261120/publico.py` desde la raíz con `PYTHONUTF8=1`. Crea una categoría y un producto nuevos por corrida mediante fixture, carga ocho unidades y opera dos ventas en Chrome por los formularios públicos. Comprueba los efectos en la misma base PostgreSQL y guarda un JSON con un nombre nuevo. Conserva el turno abierto y las dos ventas para recuperar el historial. Si queda un borrador activo después de un fallo, identificar el caso original antes de volver a ejecutar.
5. Para regenerar las vistas desde 08, usar `r1-pmv/.venv/Scripts/python.exe auditoria_por_etapas/resultados/fuente_unica_20261112/regenerar_vistas.py`. Verificar el SHA-256 de 08 en las tres cabeceras y en INDICE_DERIVADO.json. La conclusión por variante está en [ETAPA-03](../../ETAPA-03.md#precio-03-publico).
